## Постановка

−Δu = 1 в области D = {x² − 4y² > 1, 1 < x < 3}, u = sin(x + y) на границе.
D — часть плоскости между правой ветвью гиперболы x = √(1 + 4y²) и прямой
x = 3, |y| < √2; область выпуклая, площадь 3√2 − ½·arsh(2√2) ≈ 3.36127.

Метод фиктивных областей с продолжением по младшему коэффициенту:
прямоугольник Π = (0.91, 3.11) × (−1.65, 1.65), ε = h², h = max(h1, h2);
пятиточечная схема; CG с диагональным предобуславливанием; остановка по
‖w(k+1) − w(k)‖_E < δ, δ = 10⁻⁶.

## Решения, которые придётся объяснять на беседе

| Что | Как сделано | Почему |
|---|---|---|
| Площадь S_ij пересечения ячейки с D | Точно: интеграл ширины сечения по y через первообразную √(1+4y²) | D выпукла, сечение при фиксированном y — отрезок (g(y), 3); формула короткая и не зависит от того, как дуга режет ячейку. Самопроверка: сумма S_ij совпадает с площадью D до 10 знаков |
| Начальное приближение | w(0) = v0, CG решает систему для поправки d = w − v0 с правой частью F + Δ_h v0 | Иначе в правой части сидит Q·v0 ~ 1/h⁴ ≈ 10⁹ и съедает значащие цифры F ≈ 1. Это тот же CG, что в задании, — задание разрешает любое w(0) |
| Π = (0.91, 3.11) | x = 3 — узел любой сетки с M, кратным 20; стороны 2.2 : 3.3 = 2 : 3, как сетки таблиц, поэтому h1 = h2 | С Π = (0.9, 3.1) ошибка против эталона застревала на 4·10⁻³ на сетках 20, 40, 80 — см. «История» |
| Контроль J(d) = −½(B + r, d), d = w − v0 | Считается в том же цикле, что обновление w и r; рост больше 10⁻¹⁰·|J| — откат к w(k) и перезапуск | Рекомендация задания (раздел 5). На всех прогонах перезапусков 0 |
| Декомпозиция | Px × Py = P; неизвестные имеют единственного владельца. Из разложений P выбирается лучшее по форме замкнутых геометрических доменов с общей границей | Требование задания: nx/ny ∈ [1/2, 2], размеры блоков отличаются не больше чем на 1 |
| Обмены | Перед каждым A·p — теневые слои 4 соседей (Isend/Irecv; столбцы упаковываются), 2 Allreduce по 2 числа на итерацию | Пятиточечному шаблону углы не нужны; скалярные произведения склеены попарно, чтобы реже синхронизироваться |
| Гибрид | Те же циклы с `#pragma omp parallel for`, обмены между циклами, MPI_THREAD_FUNNELED | Код CG один на все четыре программы (`src/solver.h`) — отличается только реализация обменов |

На сетке 80×80 при P = 2 уникальные внутренние неизвестные распределены
как 79×40 и 79×39. Геометрические домены покрывают весь прямоугольник,
пересекаются по общей границе y = 0 и содержат по 81×41 узлу;
81/41 < 2. Теневые копии не используются для выполнения ограничения.
Программа выводит размеры владения и доменов отдельно, а `src/decomp.h`
выбирает разложение по второму критерию. На 4×6/P=4 это меняет выбор
с 1×4 на 2×2. Перебор 38 416 конфигураций проверяет покрытие, единственность
владения и размеры доменов. Трактовка явно описана в отчёте;
её согласование преподавателем не утверждается.

## Проверки и коды завершения

```bash
make -j4
bash tests/run_local.sh
# Только регрессии; путь должен указывать на новый каталог:
uv run tests/regression.py --output-dir /path/to/new/test-results
```

Для локальных проверок нужны Python 3.8+, `uv` и Open MPI. Python-зависимости
описаны в заголовках скриптов. Полный прогон проверяет сетки задания,
сравнивает полные поля всех четырёх CPU-версий (включая границы), решает
малые системы независимо и проверяет ошибки относительно сохранённого
FEM-эталона. Дополнительные регрессии охватывают неравномерную декомпозицию,
плохие параметры, несходимость и ошибки записи. Их результаты сохраняются,
существующий каталог регрессий не перезаписывается.

Коды завершения: `0` — успех, `1` — неверные параметры/невозможное
разбиение, `2` — ошибка записи, `3` — CG не достиг критерия или произошёл
численный сбой. MPI передаёт ошибку записи всем процессам. Строка `RESULT`
печатается только после успешного расчёта и запрошенной записи; поле
`status` равно `converged` либо `exact_residual`. Причины неуспеха
выводятся как `SOLVER_ERROR status=...`.

`--maxit` принимает значения от 1 до числа внутренних неизвестных,
`--delta` — конечное положительное число. Числа с посторонними символами
и сетки, переполняющие используемые int-индексы, отклоняются.

`tools/compare_solutions.py` проверяет всё поле с абсолютным допуском
1e-10. `tools/compare_reference.py` завершает процесс с ошибкой при
превышении допуска, NaN или бесконечности. Регрессионные пределы для
сеток 20×20, 40×40, 80×80, 400×600, 800×1200 соответственно равны
4.5e-3, 3.8e-3, 3.2e-3, 8e-4, 5e-4. Они заданы по сохранённым FEM-проверкам
с запасом и не являются теоретическими оценками метода. Для другой сетки
нужен явный `--max-error`.

Сборщики таблиц исключают явно неуспешные статусы. Старые логи без `status`
поддерживаются с предупреждением: наличие старой строки `RESULT` само
по себе не удостоверяет сходимость. Исторические замеры не переписывались.

  с `-qsmp=omp`.
- 400×600 на 16 исполнителях масштабируется хуже 800×1200 (13.6 против
  15.4 у OpenMP): итерация на 16 нитях занимает ~0.1 мс, и накладные
  расходы на синхронизацию (4 параллельных цикла и 2 редукции на
  итерацию) в ней заметнее.
- Гибрид 4×2 на 800×1200 даёт эффективность 0.79 при 0.91 у 4×4 —
  воспроизводится (серии 3 и 4). Гипотеза «две нити на одном ядре»
  опровергнута серией 4: ключ `--binding` показывает, что без явной
  привязки у каждой нити своё ядро. Счёт масштабируется ровно (setup
  4×2 вдвое быстрее 4×1), лишнее время — в ожидании на allreduce
  (0.10–0.15 с против 0.035 у 4×1). На тех же 8 ядрах MPI-8 — 0.66 с,
  гибрид 4×2 — 0.81–0.90 с. Причина открыта; следующий опыт — режим
  ожидания нитей, серия 5 (подготовлена, см. ниже).
- **`OMP_PLACES=cores` в гибриде не использовать.** Замедление в 90–400 раз:
  среда OpenMP компилятора XL строит места по всему узлу, а не по ядрам,
  которые LSF выдал процессу, и все процессы узла садятся на ядра 0, 1, …
  (серия 4, `results/polus/s4/*_places.*`). Без привязки нити и так
  расходятся по своим ядрам.

## Как ставить новую серию на Polus

Код лежит в `~/task1` на Polus, собран IBM XL.

1. Зайти: `ssh -i ~/.ssh/id_rsa_hpc edu-cmc-skmodel26-609-02@polus.hpc.cs.msu.ru`

   (выход из записи — `exit`).
3. Сгенерировать задания новой серии: `SERIES=s4 bash jobs/gen_jobs.sh`
   (по умолчанию узлы c3/c4 и монопольный режим; `EXCLUSIVE=0` — без него;
   имя серии обязательно новое — s1–s5 уже заняты).
4. Поставить в фоне:
   `REPEAT=3 nohup bash jobs/submit.sh base t1 t2 t3 > results/polus/submit_s4.log 2>&1 &`
5. Следить: `bjobs`; `tail results/polus/submit_s4.log`.
6. Забрать результаты на ноутбук (из папки `task1`):
   `rsync -a -e "ssh -i ~/.ssh/id_rsa_hpc" edu-cmc-skmodel26-609-02@polus.hpc.cs.msu.ru:task1/results/polus/ results/polus/`
7. Таблицы и графики:
   `uv run tools/collect.py --plot results/polus/s4/speedup.png results/polus/s4/*.out`
   `uv run tools/plot_solution.py results/polus/s4/sol_800x1200.bin`

Пока задачи стоят в очереди, не пересобирать программы: LSF запускает тот
файл, который лежит на диске в момент старта.

- нет строк `WARNING: OpenMP threads differ` — иначе `OMP_NUM_THREADS`
  не дошёл до второго узла;
- `iters` одинаковое у всех версий на одной сетке (599 на 400×600, 1018
  на 800×1200);
- `bind cpu list` — столько ядер, сколько заказано (по 8 номеров на ядро);
- ни одной задачи на `polus-c2` (строка `executed on host(s)`).

## Проверка правильности

Локально (`bash tests/run_local.sh`, лог — `results/local/20261001-234636/`):

1. Сумма площадей S_ij = площадь D до 10 знаков на всех сетках.
2. Последовательная, OpenMP (1/4/16 нитей), MPI (1/2/4 процесса) и гибрид
   на 80×80 дают одинаковое ∫w = 1.843021556897 до последнего знака. На
   Polus (IBM XL, `-qstrict`) — то же число.
3. Схема, собранная заново в Python (площади — численным интегрированием,
   система — для самой w, без перехода к поправке) и решённая прямым
   методом: расхождение с CG ≤ 2.3·10⁻¹² на сетках 20, 40, 80.
4. Сверка с эталоном исходной задачи (FEM, Mathematica, устойчивость в пяти точках при сгущении менее 2·10⁻⁷),
   максимум ошибки по пяти контрольным точкам:

   | Сетка | 20×20 | 40×40 | 80×80 | 400×600 | 800×1200 |
   |---|---|---|---|---|---|
   | Ошибка | 3.8·10⁻³ | 3.3·10⁻³ | 2.8·10⁻³ | 6.1·10⁻⁴ | 4.0·10⁻⁴ |

   На проверенных сетках ошибка в точках уменьшается. Эти данные не
   устанавливают асимптотический порядок метода: меняются и сетка, и ε.
   В пересечённых границей ячейках штраф может иметь порядок h⁻⁴;
   геометрия границы и итерационная ошибка требуют отдельного контроля.
5. Повторная проверка 03.11.2026 сравнивает полные поля с сеточным эталоном
   δ = 10⁻¹³. На 800×1200 при δ = 10⁻⁶ выполнено 1018 итераций, но
   максимальная итерационная ошибка равна 2.18·10⁻⁴. При δ = 10⁻⁸ она
   падает до 1.42·10⁻⁶ (1508 итераций), при δ = 10⁻¹⁰ — до 9.03·10⁻⁹
   (1991 итерация). Прежнее обоснование допуска по изменению ∫w было
   недостаточным: интеграл может скрывать локальную ошибку. Для более
   точного поля используйте проверенный `--delta 1e-8` и контролируйте
   результат; исторические таблицы скорости относятся к δ = 10⁻⁶.

## Воспроизведение отчёта

CSV всех итераций и сводки хранятся в `report/data/`, рисунки — в
`report/figures/`. Сеточный эталон при δ = 10⁻¹³ проверен ужесточением
с 10⁻¹² и независимым прямым решателем на малых сетках. FEM-эталон
пересчитан Mathematica; нормы полей дополнительно проверены WolframScript.
Погрешность относительно FEM оценивается только в пяти указанных точках.

```bash
make -j4 all trace_cg
uv run tools/build_report_data.py --work-dir /path/to/report-work
wolframscript -file tests/reference.wls
wolframscript -file tests/verify_report.wls
SKIPOD_REPORT_WORK=/path/to/report-work wolframscript -file tests/verify_trace_fields.wls
SKIPOD_REPORT_BUILD_DIR=/path/to/latex-work bash report/build.sh
```

`build_report_data.py` сохраняет бинарные поля и логи в указанном рабочем
каталоге и повторно использует расчёты с теми же исходниками и аргументами.
Диагностика каждой итерации не включается в замеры скорости.
Для сборки PDF нужны `uv`, XeLaTeX с polyglossia и шрифты Times New Roman,
Arial, PT Mono. `report/build.sh` обновляет таблицы по JSON/логам,
собирает документ дважды и сохраняет `output/pdf/skipod-task1-report.pdf`.

## История работы (для отчёта)

- **Векторизация.** Первая OpenMP-версия на одной нити считала 800×1200
  за 4.2–4.8 с против 2.0 с у последовательной. Диагностика
  (`clang -Rpass-missed=loop-vectorize`): внутренние циклы в
  параллельных областях не векторизовались — общие переменные цикла
  компилятор видит через указатели и не может исключить алиасинг с
  записями в массивы. Работа над строкой вынесена в функции `row_*` со
  скалярами по значению и `__restrict__` — OpenMP(1) сравнялась с
  последовательной.
- **Выбор Π.** Сначала Π = (0.9, 3.1). Сверка с эталоном показала, что
  ошибка на сетках 20, 40, 80 не убывает (4.0·10⁻³ на всех трёх).
  Причина: узел x = 2.99 есть на всех вложенных сетках, его ячейка
  разрезана прямой x = 3, и он закрепляется на v0 — эффективная
  граница сдвинута на 0.01 одинаково на всех сетках. После сдвига Π
  так, чтобы x = 3 была узлом, ошибка стала убывать. Логи до и после —
  `results/local/20261001-234533/` и `results/local/20261001-234636/`.
- **Polus.** Сборка XL и GCC 4.8.5 без предупреждений (для XL `asinh`
  взят из `<math.h>`: в `<cmath>` до C++11 его нет). Первая группа задач
  `check` — 01.10.2026, JOBID 1594700–1594710.
- **Серия 1** (04.10, JOBID 1594904–1594929, по одному прогону). Аномалии:
  гибрид 2×1 вдвое медленнее MPI на 2 процессах, MPI на 800×1200 с
  эффективностью ~0.6. Все такие прогоны попали на узел polus-c2.
  Проверка (группа `nodes`, JOBID 1594930–1594935): seq 800×1200 на c2 —
  8.27 с, на c3/c4 — 5.0–5.1 с, повторы сходятся в 0.5%. Частота по
  `/proc` и загрузка у c2 такие же (`cpufreq_*`, `load_*`), причину
  из-под пользователя не установить. Решение — задания только на c3/c4
  (`#BSUB -m`). Логи — `results/polus/`, таблицы — `tables_s1.md`.
- **Серия 2** (JOBID 1594941–1595018, три повтора, c3/c4). Аномалии
  серии 1 ушли. Разброс между повторами до 58%: медленные повторы шли
  одновременно с другой моей задачей на том же узле — ядра разные, а
  память общая. Решение — монопольный узел (`#BSUB -x`). Логи —
  `results/polus/s2/`.
- **Серия 3** (JOBID 1595019–1595096) — итоговая, см. «Результаты на
  Polus». Разброс 0–3% в большинстве строк; остаточные выбросы — один
  медленный повтор из трёх, время у него уходит в ожидание на allreduce.
- **Серия 4** (JOBID 1595097–1595144, группа `bind`). Проверка гипотезы
  про гибрид 4×2: добавлен ключ `--binding` (первая версия падала на двух
  процессах — переполнение буфера имени узла, поймано локально). Гипотеза
  опровергнута; `OMP_PLACES=cores` оказался ловушкой — см. «Результаты на
  Polus». Логи — `results/polus/s4/`.
- Ошибка по дороге: в описании серии 2 сверхлинейность MPI-32 была
  объяснена кэшем L3 без проверки; в следующем коммите на Polus
  объяснение отозвано (блок MPI-16 тоже помещается в L3, а ускорение
  там линейное).
